## Анализ проблемы в исходном коде

**Проблема**: между проверкой баланса и фактическим списанием другой поток может изменить баланс. Например:
- Поток 1 проверяет: баланс = 1000, можно снять 1000
- Поток 1 делает Sleep(20)
- Поток 2 снимает 500, баланс становится 500
- Поток 1 просыпается, читает баланс (уже 500) и списывает 1000 → баланс = -500

## Сравнение CRITICAL_SECTION и MUTEX

| Критерий              | CRITICAL_SECTION                     | MUTEX                                       |
| --------------------- | ------------------------------------ | ------------------------------------------- |
| **Область видимости** | Только в пределах одного процесса    | Межпроцессная (с именованными мьютексами)   |
| **Скорость**          | Быстрее (пользовательский режим)     | Медленнее (переход в режим ядра)            |
| **Ожидание**          | Только активное ожидание (Spin lock) | Может переводить поток в состояние ожидания |
| **Рекурсивность**     | Поддерживает рекурсивные захваты     | Зависит от реализации, обычно поддерживает  |

## Анализ FileLockingCriticalSection

**FileLockingCriticalSection** используется для синхронизации доступа к файлу при операциях чтения/записи. Это правильно, но недостаточно, потому что:

1. **Он защищает только отдельные операции с файлом**, но не защищает логическую целостность последовательных операций (проверка → действие).

2. **Для однопроцессного приложения** можно использовать только CRITICAL_SECTION, но нужно защищать всю бизнес-логику (функции Deposit/Withdraw), а не только файловые операции.

3. **Для многопроцессного приложения** (два экземпляра программы) нужен MUTEX, так как CRITICAL_SECTION работает только в пределах одного процесса.

## Выводы

1. **FileLockingCriticalSection** правильно защищает от конфликтов при одновременном доступе к файлу, но не решает проблему логической целостности операций.

2. **Для полной синхронизации** необходимо защищать всю бизнес-логику (функции Deposit/Withdraw), а не только файловые операции.

3. **Выбор между CRITICAL_SECTION и MUTEX** зависит от требований:
   - Для синхронизации только в пределах одного процесса достаточно CRITICAL_SECTION
   - Для синхронизации между разными процессами необходим MUTEX
