# Лабораторная работа №3.  
## Планировщик ОС. Приоритеты потоков. Базовый уровень.

### Цели и задачи
Познакомиться с работой планировщика операционной системы, исследовать порядок работы двух потоков в многопроцессорной системе.

### Постановка задачи
На основе лабораторной работы №1 разработать программу, которая:

- Создает два потока, передает порядковый номер потока в потоковую функцию.
- Выполняет в цикле в каждом потоке заданное количество операций и пишет в файл время выполнения каждой операции в миллисекундах 
- (можно использовать функцию `timeGetTime`) от начала работы программы и порядковый номер потока:

```text
1|12
1|23
1|25
...
```

- На основе полученных данных построить в Excel наглядные Plot диаграммы (см. пример рядом с заданием).

### Требования
- Программа должна быть реализована в виде консольного приложения и использовать Windows SDK, язык программирования – С++.
- Построить в Excel Plot графики времени выполнения для каждого потока. Убедиться, что потоки работают параллельно. Если по 
- графикам видно, что потоки работают не одновременно, пересмотреть систему логирования. Возможно, файл является общим ресурсом и 
- возникают «гонки» потоков.

# Выводы по лабораторной работе

## Для системы с одним доступным ядром процессора

1. **Реализуется только квазипараллельное выполнение (concurrency)** — потоки работают не одновременно, а чередуются через быстрое переключение контекста на единственном физическом ядре.
2. **Приоритеты потоков оказывают заметное влияние** на распределение процессорного времени. Поток с более высоким приоритетом получает больше квантов времени, но не монополизирует ядро полностью.
3. **Наблюдается четкое чередование потоков** во временных метках, что свидетельствует о работе планировщика по выделению квантов времени каждому потоку на одном ядре.
4. **Производительность ограничена частыми переключениями контекста**, которые создают дополнительные накладные расходы.

## Для системы с несколькими доступными ядрами процессора

1. **Достигается истинное параллельное выполнение (parallelism)** — потоки работают одновременно на разных физических ядрах одного процессора.
2. **Приоритеты практически не влияют** на производительность при наличии свободных ядер, так как каждый поток получает собственное физическое ядро.
3. **Временные метки потоков практически совпадают**, подтверждая одновременное выполнение на разных ядрах.
4. **Производительность значительно выше** благодаря отсутствию переключений контекста между потоками, выполняющимися на разных ядрах.

## Общие выводы и различия

1. **Ключевое различие** — в первом случае потоки конкурируют за одно физическое ядро процессора, во втором — вычислительные ресурсы распределены между несколькими ядрами.
2. **Эффективность приоритетов обратно пропорциональна** количеству доступных ядер: на 1 ядре — значительное влияние, при избытке ядер — минимальное.
3. **Планировщик ведет себя по-разному**: при избытке ядер он просто распределяет потоки по доступным ядрам, при недостатке — реализует сложные алгоритмы планирования и балансировки нагрузки.

## Различие между параллелизмом и параллельным выполнением

1. **Concurrency (параллелизм на одном ядре)** — это логическая одновременность через быстрое переключение, создающая иллюзию параллельной работы на одном физическом ядре.
2. **Parallelism (параллельное выполнение на нескольких ядрах)** — это физическая одновременность, когда инструкции разных потоков выполняются в один момент времени разными ядрами процессора.
3. **Concurrency улучшает отзывчивость** системы, а **parallelism улучшает производительность** вычислительных задач.

## Роль планировщика ОС зависит от доступных ресурсов

1. **При избытке ядер** планировщик выступает как распределитель ресурсов, стремясь загрузить все ядра процессора равномерно.
2. **При недостатке ядер** планировщик становится арбитром, решающим сложные задачи:
   - Определение очередности выполнения потоков на ограниченном количестве ядер
   - Балансировка между приоритетами и справедливостью распределения времени ядра
   - Минимизация накладных расходов на переключение контекста
3. **Планировщик адаптируется к аппаратному контексту**: на многоядерных процессорах его роль менее критична, на системах с малым количеством ядер — определяющая.

## Общие фундаментальные выводы

1. **Аппаратные возможности (количество и архитектура ядер процессора) определяют архитектурные подходы** — нельзя эффективно распараллелить задачу на одноядерном процессоре так же, как на многоядерном.
2. **Абстракция потоков в Windows унифицирована**, но реализация радикально отличается в зависимости от доступного количества физических ядер процессора.
3. **Эффективность многопоточного программирования зависит от понимания целевой платформы** — оптимизации для систем с большим количеством ядер могут быть контрпродуктивными для систем с ограниченными ядерными ресурсами.
4. **Синхронизация остается критически важной** в любом сценарии, но причины разные:
   - При работе на одном ядре — для корректного чередования и предотвращения состояний гонки
   	- При работе на нескольких ядрах — для обеспечения согласованности данных между разными ядрами процессора и кэшами выполняться на разных ядрах одновременно.
