**Лабораторная работа №2**  
**Параллельная обработка непересекающихся данных**

---

### **Цели и задачи**  
Познакомиться с метриками параллельных программ, исследовать зависимость метрик от количества доступных ядер и количества потоков.

---

### **Постановка задачи**  
Реализовать программу, которая:  
1. Читает входной BMP-файл.  
2. Выполняет эффект размытия.  
3. Сохраняет картинку в другой файл.  

Обработка изображения выполняется в потоках. При реализации использовать один из трёх вариантов деления обрабатываемых данных (номер варианта – по списку группы). Алгоритм эффекта размытия можно выбрать самостоятельно.

---

### **Варианты заданий для программы в параллельном исполнении**  
1. **Горизонтальное деление данных** — матрица пикселей делится на горизонтальные полосы по количеству потоков.  
2. **Вертикальное деление данных** — матрица пикселей делится на вертикальные полосы по количеству потоков.  
3. **Деление данных квадратами** — матрица пикселей делится на квадраты. Количество квадратов ровно \( N^2 \), где \( N \) – количество потоков. Каждый поток обрабатывает \( N \) произвольных квадратов.

---

### **Требования**  
1. Реализация в виде консольного приложения на C++ с использованием Windows SDK.  
2. Имена входного и выходного BMP-файлов передаются через параметры командной строки.  
3. Количество потоков и количество ядер задаются через командную строку.  
4. Программа должна выводить время работы (в миллисекундах) для последовательного и параллельного вариантов, включая операции чтения/записи файлов.  
5. При слишком быстром выполнении применять функцию размытия в цикле для достижения времени выполнения 0.5–1 секунда.  
6. Построить в Excel графики для следующих параметров в зависимости от количества потоков \([1;16]\):  
   - Время выполнения (\( T_N \), где \( N \) – количество потоков).  
   - Ускорение (\( S_N = T_1 / T_N \)).  
   - Эффективность распараллеливания (\( E_N = S_N / N \)).  
7. Графики построить для однопроцессорной, двухпроцессорной, трёхпроцессорной и четырёхпроцессорной системы (эмуляция через `SetProcessAffinityMask`).  
8. Итоговые материалы:  
   - Исходный код и исполняемые файлы (Release) выложить на GitHub.  
   - В файле `readme` указать ссылку на Google Sheets с графиками и выводами.  
   - Название документа: `ПП_[год]_ПС-[ваша группа]-[Фамилия]`.

## **Выводы по лабораторной работе**

При исследовании параллельной обработки изображений выявлены ключевые закономерности:

1. **Ускорение обработки** наблюдается при увеличении количества потоков, но с заметным **снижением эффективности** при превышении числа физических ядер процессора.

2. **Нелинейность уменьшения времени выполнения** объясняется возрастанием накладных расходов на:
   - Создание и управление потоками
   - Переключение контекста между ними
   - Конкуренцию за доступ к памяти

3. **Оптимальная конфигурация** достигается при равенстве количества потоков числу доступных ядер процессора, обеспечивая максимальное ускорение при минимальных накладных расходах.

4. **Особенности алгоритма размытия** делают его хорошо подходящим для параллелизации благодаря локальности данных и независимости обработки различных областей изображения.

5. **Практический результат**: программа демонстрирует реальные преимущества многопоточной обработки для вычислительно сложных операций с изображениями, при этом наглядно показывая физические ограничения параллелизма на уровне аппаратного обеспечения.
