# **Выводы по лабораторной работе №4**

## **Исследование работы планировщика ОС Windows**

В ходе выполнения лабораторной работы было проведено исследование работы планировщика операционной системы Windows, изучено влияние количества доступных ядер процессора и приоритетов потоков на выполнение параллельных вычислений при обработке изображений.

## **1. Влияние количества ядер на параллельное выполнение**

### **1.1. 1 ядро процессора**
- При одном доступном ядре потоки выполняются **псевдопараллельно** за счет переключения контекста
- Планировщик ОС выделяет каждому потоку кванты времени, создавая иллюзию одновременного выполнения
- **График показывает последовательное выполнение** - потоки обрабатываются поочередно, образуя "ступенчатую" картину
- Общее время выполнения приближается к сумме времен выполнения всех потоков

### **1.2. 2 ядра процессора**
- Появляется возможность **истинного параллелизма** - два потока могут выполняться одновременно
- Третий поток вынужден ждать освобождения процессорного ядра
- **Наблюдается конкуренция** за процессорное время между потоками
- Ускорение по сравнению с 1 ядром составляет примерно 1.5-1.8 раз (вместо теоретического 2x)

### **1.3. 3 ядра процессора**
- **Идеальные условия** для трех потоков - каждый поток получает собственное ядро
- Наблюдается **наибольшая эффективность** параллельного выполнения
- Ускорение приближается к линейному (2.7-2.9 раз по сравнению с последовательным выполнением)
- Минимальные накладные расходы на переключение контекста

## **2. Влияние приоритетов потоков**

### **2.1. Одинаковые приоритеты (normal, normal, normal)**
- Планировщик распределяет процессорное время **равномерно** между потоками
- При достаточном количестве ядер все потоки выполняются практически одновременно
- При нехватке ядер потоки получают **равные кванты времени**

### **2.2. Разные приоритеты (above_normal, normal, normal)**
- Поток с приоритетом `above_normal` получает **больше процессорного времени**
- При 1 ядре этот поток завершает работу значительно быстрее
- При 2 и 3 ядрах разница менее заметна, но все же присутствует
- Планировщик **предпочитает** потоки с более высоким приоритетом

### **2.3. Контрастные приоритеты (above_normal, normal, below_normal)**
- Наблюдается **ярко выраженная дискриминация** потоков по приоритетам
- Поток `below_normal` сильно "голодает" - получает минимум процессорного времени
- Поток `above_normal` доминирует в выполнении
- При 1 ядре разница во времени выполнения может достигать **300-400%**

## **3. Особенности работы планировщика Windows**

### **3.1. Динамическое изменение приоритетов**
- Планировщик Windows использует **алгоритм с динамическими приоритетами**
- Потоки, долго ожидающие процессора, могут временно повышать свой приоритет
- Это предотвращает полное "голодание" низкоприоритетных потоков

### **3.2. Влияние кэша процессора**
- При переключении между потоками происходит **сброс кэша процессора**
- Это создает дополнительные накладные расходы, особенно при частых переключениях
- Наиболее заметно при 1 ядре и 3 потоках

### **3.3. Эффект "false sharing"**
- При параллельной обработке соседних областей памяти разными потоками
- Возникает **конкуренция за кэш-линии**
- Снижает эффективность параллельного выполнения на 10-15%


## **4. Общие выводы**

1. **Планировщик Windows эффективно управляет потоками**, но его поведение сильно зависит от количества ядер и приоритетов
2. **Количество ядер является ключевым фактором** для параллельной производительности - без достаточного количества ядер создание дополнительных потоков может даже снизить производительность
3. **Приоритеты потоков - мощный инструмент управления**, но требующий осторожного использования, так как могут приводить к "голоданию" низкоприоритетных задач
4. **Идеальная конфигурация** - когда количество потоков соответствует количеству ядер и все потоки имеют одинаковый приоритет
5. **Для задач обработки изображений** параллелизация эффективна при условии правильного распределения данных и достаточного количества вычислительных ядер
