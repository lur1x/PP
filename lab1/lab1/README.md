
# Лабораторная работа №1
## Работа с потоками

### Цели и задачи
Получить навыки создания, выполнения кода в потоке, передачи параметров в поток, ожидания окончания всех потоков.

### Постановка задачи
Реализовать программу, создающую N потоков, в каждый из которых передается его порядковый номер (1, 2, …, N). Каждый поток выводит на экран текст:

«Поток №<номер потока> выполняет свою работу»

где `<номер потока>` - порядковый номер потока, переданный ему в качестве параметра.

### Требования
1. Реализовать консольное приложение на С++, для работы с потоками использовать функцию `CreateThread` (Windows SDK).
2. Количество потоков передавать приложению в командной строке.
3. Приложение должно ожидать окончание работы всех потоков, после чего корректно завершаться. Для ожидания окончания работы всех потоков используйте функцию `WaitForMultipleObjects` (Windows SDK).
4. Разработать и сдать программу на занятии.

### Шаблон для ленивых ;)

```cpp
#include "stdafx.h"
#include <windows.h>
#include <string>
#include <iostream>

DWORD WINAPI ThreadProc(CONST LPVOID lpParam) 
{
    // 
    // ?? тут выполняется полезная работа потока
    //

    ExitThread(0); // функция устанавливает код завершения потока в 0
}

int _tmain(int argc, _TCHAR* argv[])
{
    // создание двух потоков
    HANDLE* handles = new HANDLE[2];
    handles[0] = CreateThread(NULL, 0, &ThreadProc, NULL, CREATE_SUSPENDED, NULL);
    handles[1] = CreateThread(NULL, 0, &ThreadProc, NULL, CREATE_SUSPENDED, NULL);

    // запуск двух потоков
    ResumeThread(handles[0]);
    ResumeThread(handles[1]);
    
    // ожидание окончания работы двух потоков
    WaitForMultipleObjects(2, handles, true, INFINITE);
    return 0;
}
```


# Ход работы:
## 1. По шаблону сделал лабораторную, добавив парсинг аргументов:
   
```cpp
#include <windows.h>
#include <string>
#include <iostream>
#include <tchar.h>


DWORD WINAPI ThreadProc(CONST LPVOID lpParam)
{
	int threadNum = *(int*)lpParam;

	std::cout << "Поток №" << threadNum << " выполняет свою работу" << std::endl;

	ExitThread(0);
}

int _tmain(int argc, _TCHAR* argv[])
{
	setlocale(LC_ALL, "RU");

	if (argc != 2)
	{
		std::cerr << "Ошибка, для запуска программы используйте: program.exe <количество_потоков>" << std::endl;
		return 1;
	}

	unsigned int N = 0;

	try 
	{
		int temp = std::stoi(argv[1]);
		if (temp < 0)
		{
			std::cerr << "Ошибка: количество потоков не может быть отрицательным." << std::endl;
			return 1;
		}

		N = static_cast<unsigned int>(temp);
	}

	catch (const std::invalid_argument&)
	{
		std::cerr << "Ошибка: аргумент не является числом." << std::endl;
		return 1;
	}

	catch (const std::out_of_range&) 
	{
		std::cerr << "Ошибка: слишком большое число." << std::endl;
		return 1;
	}

	if (N == 0) 
	{
		std::cerr << "Ошибка: количество потоков должно быть больше 0." << std::endl;
		return 1;
	}

	unsigned int* threadIds = new unsigned int[N];


	HANDLE* handles = new HANDLE[N];

	for (unsigned int i = 0; i < N; i++)
	{
		threadIds[i] = i + 1;
		handles[i] = CreateThread(NULL, 0, &ThreadProc, &threadIds[i], CREATE_SUSPENDED, NULL);
	
		if (handles[i] == NULL)
		{
			std::cerr << "Ошибка при создании потока " << (i + 1) << std::endl;
			
			for (unsigned int j = 0; j < i; ++j)
			{
				CloseHandle(handles[j]);
			}
			delete[] handles;
			delete[] threadIds;

			return 1;
		}

	}

	for (int i = 0; i < N; i++)
	{
		ResumeThread(handles[i]);
	}

	WaitForMultipleObjects(N, handles, true, INFINITE);

	for (unsigned int i = 0; i < N; i++)
	{
		CloseHandle(handles[i]);
	}

	delete[] handles;
	delete[] threadIds;

	std::cout << "Все потоки завершили работу" << std::endl;
	return 0;
}

```

## 2. Объяснения:

CloseHandle() - закрывать дескрипторы, чтобы избежать утечки системных ресурсов.

WaitForMultipleObjects() - функция синхронизации в Windows, которая блокирует текущий поток до тех пор, пока не 
произойдет определенное событие с одним или несколькими объектами.

Синтаксис:
```cpp

DWORD WaitForMultipleObjects(
  DWORD        nCount,             // Количество объектов
  const HANDLE *lpHandles,         // Массив дескрипторов
  BOOL         bWaitAll,           // TRUE - ждать ВСЕХ, FALSE - ждать ЛЮБОГО
  DWORD        dwMilliseconds      // Таймаут в миллисекундах
);
```

в моём решении:
```cpp
WaitForMultipleObjects(N, handles, true, INFINITE) 
// N - количество потоков для ожидания
// handles - массив дескрипторов потоков
// true  - ждать завершения ВСЕХ потоков
// INFINITE - ждать бесконечно долго (пока все не завершатся)
```

HANDLE (дескриптор) в Windows - это абстрактная ссылка на системный ресурс (файл, поток, процесс, мьютекс и т.д.). 
Это не прямой указатель на память, а скорее "токен" или "билет", который система использует для идентификации ресурса.

В ресторане вы получаете номерок (HANDLE) вместо того, чтобы держать пальто (ресурс) в руках

CreateThread создает новый поток в процессе. Синтаксис:
```cpp

HANDLE CreateThread(
  LPSECURITY_ATTRIBUTES   lpThreadAttributes,   // Определяет, может ли дочерний процесс наследовать этот дескриптор.
  SIZE_T                  dwStackSize,          // Размер стека потока в байтах(0 - размер по умолчанию (обычно 1 МБ))
  LPTHREAD_START_ROUTINE  lpStartAddress,       // Указатель на функцию, которую будет выполнять поток.
  LPVOID                  lpParameter,          // Произвольные данные, передаваемые в функцию потока.
  DWORD                   dwCreationFlags,      // Флаги, управляющие созданием потока.(0 - поток запускается немедленно, CREATE_SUSPENDED - поток создается приостановленным, STACK_SIZE_PARAM_IS_A_RESERVATION - зарезервировать стек)
  LPDWORD                 lpThreadId            // Указатель на переменную для получения ID потока.
);
```

в моем решение:
```cpp
 handles[i] = CreateThread(
        NULL,                // 1. Безопасность по умолчанию
        0,                   // 2. Размер стека по умолчанию
        ThreadProc,          // 3. Функция, которую выполняет поток
        threadData,          // 4. Данные для потока (номер потока)
        CREATE_SUSPENDED,    // 5. Создать приостановленным
        NULL                 // 6. Не нужно ID потока
    );
```
узнал, что вместо CREATE_SUSPENDED можно сделать 0 и сразу запустить поток.

```cpp
 handles[i] = CreateThread(
        NULL,                // 1. Безопасность по умолчанию
        0,                   // 2. Размер стека по умолчанию
        ThreadProc,          // 3. Функция, которую выполняет поток
        threadData,          // 4. Данные для потока (номер потока)
        0,    // 5. Создать приостановленным
        NULL                 // 6. Не нужно ID потока
    );
```
Отсюда возникает вопрос: Будет ли разница в выводе, если запускать немеделенно?
Принципиальной разницы в конечном результате не будет, но есть нюансы в поведении:
- Порядок вывода может отличаться,так как во 2 случае поток может начать работать ДО создания следующего
- во 2 случае между созданием потоков есть небольшая задержка

Почему такой странный вывод в консоль?

```bash
Поток №Поток №Поток №3 выполняет свою работу
Поток №4 выполняет свою работу
2 выполняет свою работу
1 выполняет свою работу
Все потоки завершили работу
```

Планировщик сам решает, в каком порядке их запускать. Это зависит от:
* Приоритета потока (по умолчанию такой же, как у родительского)
Приоритеты в Windows (от 0 до 31):
```text
31: Real-time (критические системные потоки)
16-30: Высокие приоритеты
8-15: Нормальные (по умолчанию)
1-7: Низкие
0: System idle
```
* Квант времени (Каждому потоку выделяется квант времени, обычно 15-60 мс).
* Занятости процессора
* Количества ядер процессора
* История выполнения
Windows использует алгоритмы предсказания:
- Потоки, часто обращающиеся к диску, могут получить более низкий приоритет
- Потоки, интенсивно использующие CPU, могут получить меньший квант
- "Свежие" потоки часто получают небольшой бонус к приоритету
* Других потоков в системе

```cpp
// Примерно так работает планировщик:
void ScheduleThreads() {
    while (true) {
        // 1. Выбрать поток с наивысшим приоритетом
        Thread* nextThread = SelectHighestPriorityThread();
        
        // 2. Сохранить контекст текущего потока
        SaveCurrentThreadContext();
        
        // 3. Восстановить контекст выбранного потока
        RestoreThreadContext(nextThread);
        
        // 4. Переключиться на него
        SwitchToThread(nextThread);
        
        // 5. Подождать квант времени или событие
        WaitForTimeQuantumOrEvent();
    }
}
```

Можем ли мы повлиять на порядок?
Ограниченно:

1. Приоритеты (но это не гарантия!):
```cpp
// Создаем потоки с разными приоритетами
SetThreadPriority(threadHigh, THREAD_PRIORITY_HIGHEST);
SetThreadPriority(threadLow, THREAD_PRIORITY_LOWEST);
// Высокоприоритетный запустится скорее, но не обязательно первым
```

2. Синхронизация (надежный способ):
```cpp
// Используем события для строгого порядка
HANDLE event1 = CreateEvent(NULL, FALSE, FALSE, NULL);
HANDLE event2 = CreateEvent(NULL, FALSE, FALSE, NULL);
// Поток 1 ждет event1
// Поток 2 ждет event2
SetEvent(event1);  // Запускаем поток 1
WaitForSingleObject(thread1, INFINITE);
SetEvent(event2);  // Теперь запускаем поток 2
```

3. Создание приостановленными и ручной запуск:
```cpp
// Создаем приостановленными
HANDLE t1 = CreateThread(..., CREATE_SUSPENDED, ...);
HANDLE t2 = CreateThread(..., CREATE_SUSPENDED, ...);
HANDLE t3 = CreateThread(..., CREATE_SUSPENDED, ...);

// Запускаем в нужном порядке
ResumeThread(t3);
Sleep(10);  // Даем немного времени
ResumeThread(t1);
Sleep(10);
ResumeThread(t2);
```

Эту проблему можно решить:

Решение 1: Использовать мьютекс (рекомендуется)
Решение 2: Формировать строку целиком
Решение 3: Критическая секция Windows API
Критические секции (Critical Sections) в Windows — это еще один механизм синхронизации, аналогичный мьютексам, 
но работающий только в пределах одного процесса.

Также столкнулся с ограничением функции WaitForMultipleObjects. У нее есть ограничение на количество дескрипторов, 
которые можно передать одновременно.
эту проблему решил, с помощью:
```cpp
if (N > MAXIMUM_WAIT_OBJECTS)
{
	std::cerr << "Ошибка: количество потоков не должно превышать " << MAXIMUM_WAIT_OBJECTS << std::endl;
	return 1;
}
```
Помимо WaitForMultipleObjects, есть и другие ограничения:
- По умолчанию лимит потоков на процесс — около 2000 (зависит от версии Windows и доступной памяти).
- Общее количество потоков в системе — ограничено размером невыгружаемого пула ядра.
